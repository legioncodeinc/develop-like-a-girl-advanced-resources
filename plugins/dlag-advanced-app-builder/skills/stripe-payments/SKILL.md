# Stripe Payments Playbook

Add optional custom Stripe Elements checkout to Advanced SvelteKit apps with verified durable payment access.

1. Read the [implementation procedure](guides/workflow.md), [implementation recipes](references/recipes.md) and [local acceptance example](examples/local-proof.md).
2. Use [the custom checkout build guide](guides/custom-checkout-build.md) for the Svelte component, bounded webhook reader and durable fulfillment schema.
3. Complete the [delivery record](templates/delivery-record.md) from accepted project requirements and installed versions.
4. Load required Core Playbooks by exact Skill name: `dlag-advanced-core:identity`, `dlag-advanced-core:data-foundation`, `dlag-advanced-core:secrets`, `dlag-advanced-core:implementation-foundation`. Missing prerequisites must be reported; never resolve another plugin through sibling cache paths.
5. Implement one requested local slice, read it back and report observed checks and pending proof.

Read existing destinations and preserve unrelated work. Write/Edit only the requested local project slice and placeholder wiring. No shell, installs, credentials, provider calls, migrations, account changes, real sends or charges, deployment, commit or push. Any such operation needs its own user authorization. Distinguish saved guidance, compiled application, mock behavior, real SDK behavior and live provider proof.

Read the [edition boundaries](../../references/edition-boundaries.md). The [paired Specialist](../../agents/stripe-payments.md) follows the same scope. If delegation is unavailable, use this Playbook directly and say so.
