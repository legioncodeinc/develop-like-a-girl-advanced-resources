# Project Setup guide map

Start with [the Playbook](SKILL.md) to inspect a project, prepare a safe baseline proposal, or save the Markdown documents the owner requested. Existing project files and conventions take precedence.

- [Inspect and propose](guides/inspect-and-propose.md): root, safe evidence, conflicts and one useful next task.
- [Create project documents](guides/create-project-documents.md): requested Notebook files, destination checks and read-back.
- [Detailed baseline methods and templates](references/resource-index.md): initialization, GitHub, README, secrets, release hygiene, settings and verification.
- [Launch-readiness selection](references/readiness/asset-selection.md), [detailed ledger](references/readiness/ledger-contract.md), [web preparation](guides/readiness/prepare-web.md), [integration preparation](guides/readiness/prepare-integration.md), and [qualification](guides/readiness/qualify-assets.md): accountable owners, environments, dependencies, costs and exact readiness evidence.
- [First-session readiness](guides/08-first-session-onboarding.md): consent and evidence without home instructions, hooks or locks.
- [Operational safety boundaries](references/script-dispositions.md): validation, backups, ownership, refusal and partial-failure behavior for separately authorized setup work.
- [Setup proposal](templates/setup-proposal.md), [asset ledger](templates/asset-ledger.md), and [document set](templates/document-set.md): fillable outputs for the current documentation scope.

Configuration templates are inert proposals. This role writes only expressly requested local Markdown project documentation. A saved Notebook does not establish application setup, account configuration, configured CI or provider readiness.

## Advanced adaptation

The complete reviewed Starter methods are reused here. Read [the Advanced working guide](guides/advanced-workflow.md) alongside them. Historical research retains its original edition/provider context and dates; it is supporting evidence, not the Advanced stack selection. Runtime guidance follows SvelteKit/Vercel, Neon/Drizzle, WorkOS, Doppler and the separate Payload Next.js host with built-in editor auth. Helpers and configuration templates remain inert source for an appropriately authorized caller. Existing filenames containing `starter` are retained compatibility paths, not a different installed dependency.
