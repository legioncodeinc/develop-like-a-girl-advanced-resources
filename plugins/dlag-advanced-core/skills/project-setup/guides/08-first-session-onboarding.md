# 08. Review first-session readiness without changing the home

Keep the owner's original task in view. Advanced Project Setup is invoked directly or through its existing paired Specialist in Claude Code. It installs no SessionStart hook, home instructions or completion lock. Plugin presence and a file marker never supply consent or proof of completed setup. A marker is not completion evidence.

## Review operating instructions separately

The original home procedure personalized shared instructions from two external templates, asked consent before writing, and distinguished assistant-specific loading rules. Home and harness configuration is excluded from this documentation-only capability. Do not inspect personal home instructions, ask for personalization unrelated to the task, run an installer, or promise that a model loaded a file.

If the owner separately requests instruction installation, identify that as a different task requiring exact target and settings authorization. Its safeguards must include: preserve unrelated text; back up each existing target before replacement; update exactly one well-formed managed block; refuse symlinks, out-of-root paths, malformed/reversed markers and non-file targets; record template identities; and mark success only after every target succeeds. See [the operational safeguards](../references/script-dispositions.md). No such installation occurs here.

## Review repository readiness

1. Confirm the repository root from supplied accessible material. If none exists, report it; do not create a repository.
2. Explain the documentation model before asking a material scope question: the Notebook records current facts and decisions; requirements describe planned work and acceptance criteria; issue plans trace defects; shared interface records settle boundaries before dependent parallel work. The current Notebook location stays `library/knowledge/private/product/` unless the repository already has a convention.
3. Preserve existing task-specific authorization. A documentation request may authorize the named missing Markdown files; it does not authorize baseline configuration, dependency installation, settings or a lock file. If only inspection was requested, return the proposal.
4. Inventory existing files using [the initialization guide](01-initialization-workflow.md). Detect real code from source files/manifests, not merely `.git`. Use the packaged Project Notebook method for the authorized code-grounded documentation scope. Record missing access and unfinished coverage.
5. Verify the exact saved documentation and unperformed configuration proposals using [the verification guide](07-verification-checklist.md). Do not emit the original repository lock or infer completion from a pre-existing marker. Preserve partial/declined state honestly.

## Host and execution limits

Claude Code is the only supported assistant. Original cross-host hook, trust and installation procedures are excluded. The original Python installer requires Python 3.11+ and the original command hook requires Node.js; neither dependency is needed or installed for this documentation-only adaptation. Hook delivery, instruction loading and model compliance are distinct claims requiring their own observation. An unavailable hook does not block direct use of this Playbook.
