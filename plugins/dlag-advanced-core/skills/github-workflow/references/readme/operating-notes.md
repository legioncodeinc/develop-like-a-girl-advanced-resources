# README audience and evidence notes

A README helps the intended reader judge fit and reach the first useful outcome. Audit existing content before rewriting; preserve house style, owner decisions, legal text and useful context. Use concise value-first public/library framing or operational internal framing according to actual readers and disclosure approval. A LICENSE file does not clear private data or create publication permission.

The complete six local guides retain section ordering, badges, audience differences, draft-first design and all twelve completion checks. Word/line/command/badge counts are review heuristics, not guaranteed conversion or correctness. No minimum badge count is needed; only relevant supported signals belong. An unavailable live badge or quickstart execution remains unverified rather than silently passing or blocking every useful draft.

Readme-driven development drafts intended interfaces before code. Mark that draft explicitly and distinguish desired behavior/expected output from implementation. Review design choices with actual stakeholders before dependent work; do not promise fixed review time or unsupported measured productivity gains. Updating a design draft is not proof its code or tests exist.

For Advanced, document actual SvelteKit/Vite/Vercel setup, WorkOS identity and Neon/Drizzle data boundaries, Doppler secret references, R2 ownership/access, transactional Resend and optional custom checkout only when the receiving project uses them. Never publish secret values, internal account paths, private badge patterns or customer data. Known failure modes and mitigations need actual source evidence; do not copy fictional script names or invented healthy output as project facts.

## Supported output limits

This role returns Markdown drafts/findings in chat. It does not save a README, execute install commands, provision credentials, configure CI, generate media or publish. A separate authorized writer handles requested saves after conflict checks. Broader docs-site design and code-entity extraction remain distinct tasks. An existing README in another format is preserved; `.rst` handling is outside this method, not a claim GitHub cannot render it. Monorepo index guidance is present but no separate monorepo template is invented.
