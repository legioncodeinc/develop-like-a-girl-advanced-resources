# Use one bounded analogy

Write the factual relationship first. Choose an everyday comparison with one consistent mapping for the important actors. Preserve identity and permission as separate ideas.

For example, a library card can represent identity, while a borrowing rule represents permission. Having a card does not grant access to every restricted collection. A staff member checking the borrowing rule can represent the application server checking ownership.

State the limit beside the comparison: software exchanges data rather than people or physical cards. The comparison supplies no evidence about actual deployment or security. Remove it if it introduces a false rule or takes more effort to understand than the source.
