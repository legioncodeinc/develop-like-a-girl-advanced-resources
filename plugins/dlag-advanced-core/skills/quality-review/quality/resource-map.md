# Quality Review resources and output placement

The six-step plan-relative method, five-axis rubric, severity tree, common-gaps catalog and exact-candidate evidence companion are all locally packaged. Use [the method map](README.md) to select the full procedures; the public Quality Review entrypoint keeps the same name and tool scope.

For an actual accepted Project Notebook plan, respect its existing PRD/IRD filename and lifecycle folder. Feature/issue evidence belongs in its qa/ folder; an expressly requested standalone report follows the receiving repository's existing conventions. Do not move old evidence. No report is silently overwritten. Optional external task-tracker suffixes are not introduced as Advanced defaults.

Quality Review's actual tools are read-only. It prepares the report in chat. An authorized caller with write capability may save it at the resolved project destination and read it back; never imply this Specialist wrote it. The installed reports/ resources are references, not a mutable archive. Generated artifacts, current execution evidence and source comparison remain separate.
