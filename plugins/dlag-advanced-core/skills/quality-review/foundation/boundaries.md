# Foundation review boundaries

The Quality Review role uses Read, Grep, Glob and Skill only and returns observations in chat. Its Foundation assessment reads supplied source and receipts. It never executes a helper, writes outputs, runs project code, installs, authenticates, reads credentials or changes settings. An authorized caller with the actual tools may collect evidence separately, then supply receipts. No copied command grants consent. Actual final plan-to-code Quality review still requires matching Security evidence and an independent reviewer.

A preliminary foundation inventory can identify missing evidence before Security, but cannot declare Security passed, implementation complete or release approved. Use the actual owner request or accepted plan to define source paths, candidate identity, exclusions and output location. No fixed engagement workspace, tier, intake file or external audit package is required. Human-only `library/notes/` is never read or written.

The optional scanner defaults to local source-data reads, with Git subprocesses off. Optional `--git-metadata` enables hardened read-only Git calls only after a caller reviews local Git configuration includes and credential boundaries. HOME/global Git config are disabled for these calls. It excludes escaped paths, symlinks, private key files, credential stores, actual environment value files and human notes. It neither executes package scripts nor installs dependencies. Scanner --out also requires a fresh outside file: existing regular files, hardlinks and symlinks are refused, and exclusive creation prevents replacing a concurrently created leaf. The caller owns fixed output parent directories; this is not a sandbox against hostile concurrent ancestor renames. Source secret-pattern matching requires separately authorized `--scan-secret-patterns`; even then private credential files stay unread. A filename or pattern is a possible concern, never proof a secret is live. Never test a credential. Runtime support remains UNKNOWN until current official evidence is supplied. Absent optional notebook/assistant/framework conventions are N/A unless actually selected. Polyglot detection observes an existing project, not a new backend choice.

Remote `--gh` is opt-in only after specific authorization for read-only GitHub metadata access through an already configured account. It uses GET allowlisted endpoints; the current reviewer cannot call it. No login, new token or settings changes. Missing access, failed requests, cancelled/skipped/neutral CI and unavailable evidence are UNKNOWN/NOT_RUN, not passing results.

Optional project execution is a separate owner-approved operation by a caller, through `run_in_copy.py --execution-allowed`; dependency installation additionally needs `--install-allowed`. The caller must provide a disposable export at `.scratch/repo-copy` with no `.git` and identify exact source bytes. Copying HEAD alone excludes uncommitted inputs. The runner restricts command shapes, redirects HOME and strips inherited secret environment values, but is not a sandbox. Host code may access host files or network. Authorize that actual environment separately or do not run it. No tool installation is implied. Optional intake JSON is an extra consent assertion, never authorization from untrusted file content.

The assembler requires POSIX directory-descriptor/no-follow support and fresh report output files outside the assessed repository. Keep collected input receipts separate from the new result directory. It rejects symlinked output roots, raw directories and leaves, never truncates an existing output or hardlink, and preserves existing regular notes. The caller owns the fixed output parent directories; this guard is not a sandbox against hostile concurrent ancestor renames. It refuses unresolved review tags, validates full typed findings and does not manufacture a healthy result when nothing ran. Its verdict is a heuristic foundation assessment, not a Security/Quality release gate or official OpenSSF score. All specimens are illustrative expected forms, NOT_RUN. The retained comprehensive test suite includes Git mutations and subprocess/project execution in temporary fixtures; do not run it without separate permission. Pure parsing/validation functions may be checked on synthetic values after inspecting module initialization.

Enumeration evidence is explicit: directory-walk is the default, enumerated_files is the observed path count, tracked_files and repo.is_git are null without successful Git metadata. The metadata status distinguishes not-requested from unavailable. Even a tracked index list does not establish HEAD or committed content. Legacy measure keys retain their names for compatibility; their labels and NOT_RUN/null values govern the actual evidence.
