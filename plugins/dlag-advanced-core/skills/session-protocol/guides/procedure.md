# Work Session Protocol procedure

1. Record the assigned task, relevant authorization, existing work-unit start/deadline, active file ownership and pending questions. Do not restart a deadline on handoff or compaction. Use a reliable available clock; if none is accessible, say so and track actions with 10 tool calls counted as 5 minutes, without claiming measured elapsed time.
2. Open with Task, Start time and Questions. The limit is the earlier of the owner's deadline and 60 minutes from the measured start. A worker inherits the parent's deadline. Ask a compact material question before dependent work; continue independent authorized work.
3. Keep tasks small with one owner per path. At least every 5 minutes require a file changed, a check run, a concrete result or a question that changes the next step. Reading counts only when it changes the action. Follow the host's required update cadence if stricter.
4. At 10 minutes on one unresolved problem notify the owner. Review actual worker output every 10 minutes if workers were authorized and dispatched. Stop a worker stalled for 10 minutes. At 20 minutes without progress stop and preserve a handoff. At 45 minutes send one line with done, remaining and estimate. Stop at deadline unless the owner explicitly extended it before expiry.
5. Allow at most two identical failed attempts. A changed approach needs a reason that could change the result; after three failed approaches stop and ask. Do not rerun a passing check unless a relevant input changed. Do not poll unchanged state in tight loops.
6. Authorization follows the actual task across an authorized handoff. Do not manufacture repeated approval gates. New destructive actions, external effects, credentials, spend, installs, configuration changes and shared-branch changes require explicit scope-specific approval when not already granted. These read-only Specialists cannot perform those actions even with approval; route to an authorized implementation tool later.
7. Close with Status, Delivered, Verified, Not done, Questions for the owner, and Out of scope noticed only. Quote failures accurately with secrets redacted. Identify direct use versus real delegation. Never claim a watcher, timer or saved memory exists unless actually configured and observed.

Use [the result template](../templates/result.md) and identify all unperformed actions as proposed or unproven.
