# Keep an Advanced build moving

Use the owner's scope and time allowance. A planning or review role cannot acquire write, execution or provider access simply by delegating. A caller with those tools can apply the same Playbook directly within the owner's authorization.

Before a parallel task starts, give it the accepted slice, owned files, input/output contracts, dependency versions, relevant Playbook, deadline and expected result. Shared layout, schema and package files each need one owner. Tell every worker that other work exists and must be preserved.

Check actual progress at useful intervals: saved files, checked examples or a finding that changes the next action. A repeating plan or unchanged status is not progress. If a worker stalls, inspect the exact blocker, stop duplicate work and split or reassign only the remaining authorized part. Do not dispatch more agents to the same contested file.

When a task is blocked by provider access, preserve local source and mocks and continue an independent requested slice. State precisely what remains unverified. Do not simulate provider success to make a milestone appear complete or add a new service to avoid an unresolved choice.

Handoff includes the current branch/project, owned files, accepted decisions, unfinished behavior, checks with results, open questions and authorized next action. Reuse the existing task document or result template. Do not create another tracker or background automation for a short task. At the owner's stop/deadline, save coherent work and stop the workers too.
