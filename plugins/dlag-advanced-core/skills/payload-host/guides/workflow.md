# Payload host procedure

1. Inspect the installed Payload 3, Next.js, React, postgres adapter and storage adapter versions and official compatibility. Next.js is only the CMS host in this edition. Keep required route groups, generated import map, layout and API routes from the matching installed Payload host. Do not convert the customer app to Next.js.
2. Configure `apps/cms` with `@payloadcms/db-postgres` and a dedicated Neon `payload` schema/role (confirm the installed adapter supports its experimental schemaName option), push:false to disable automatic development schema writes, fail-closed required env values from Doppler, Lexical editor, collections and public site settings. Do not introduce fallback production secrets or let Drizzle migrate Payload tables. Payload migration generation/execution and accounts remain separate authorized actions.
3. Use built-in Payload editor accounts. An `editor` may create/edit/draft/publish content; only `admin` manages editors and role fields. Anonymous cannot create users. A WorkOS customer session grants no CMS role. Bootstrap first admin only through an explicitly authorized flow, never a public signup/default password.
4. Apply collection read rules: authenticated editors may read drafts; anonymous returns a query requiring `_status=published`. Define collection create/update/delete and role field create/update explicitly. User reads are self/admin only and sensitive user fields stay private. Use native `_status` from versions.drafts, not a parallel user-controlled status.
5. In CMS Local API calls use `overrideAccess: false`, a validated editor user and request context. Local API otherwise bypasses access control by default. Never expose generic client-controlled collection, `overrideAccess`, depth, query or credential proxy parameters.
6. Implement private draft preview as in recipes. Preview does not authorize a broader CMS identity. Public REST read filters and published cache remain independent. Publish/unpublish must invalidate only the published route and never make draft media globally readable.
7. Store uploads in private R2 via `@payloadcms/storage-s3` for this Node/Vercel host. Preserve Payload file access checks. Do not copy the public adapter example's `disablePayloadAccessControl: true`, public ACL or public bucket URL. Apply MIME, byte and image dimension limits plus quarantine/scan before release. File metadata visibility and actual bytes need separate checks.
8. Save host/collection/types/import-map changes only in assigned app paths. Report package generation/build, editor authorization, drafts, publish/unpublish, preview and real storage tests separately. A static config sketch is not a compiled Payload app or a working admin login.

Use [the collection module](../references/collections.md) for complete editor/admin field rules, draft-enabled Pages/Posts, private Media and public SiteSettings. The module also names the host, generated types and migration integration steps.
