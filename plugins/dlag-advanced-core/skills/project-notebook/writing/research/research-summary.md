# Craft reference: framework and qualification

## Four reader intents

Diataxis separates learning by doing (tutorial), completing an already chosen task (how-to), consulting complete facts (reference) and understanding causes/trade-offs (explanation). Use the compass and three-question classification in guide 00 before prose editing. A document can link to another mode without forcing every reader through all modes. A substantial second reader goal usually needs a proposed split, with actual file changes separately authorized.

## Structure and style

The inverted pyramid leads an explanation or opening paragraph with the most important supported fact, followed by context and optional detail. Procedural steps retain dependency order, and reference retains complete information. Use the three-layer model, opening-sentence test and heading patterns in guide 01 rather than rearranging execution order for visual prominence.

A supplied house style takes precedence. Otherwise use clear active voice, procedural second person/imperatives, factual reference wording, consistent headings/register and conditions before actions. Be direct about observed facts and honest about unknowns. Brand imitation from supplied samples is an explicitly inferred best-effort pattern, never a claim of an unavailable organization's official rules. Guide 03 contains the full style tables, exceptions, override protocol and conditional-instruction method.

## Complete examples and qualification

The full 12-item code checklist checks claimed behavior, real prerequisites, language fences, introductions, omission comments, annotations, clear arguments, safe artificial values, actual version/runtime checks, visible output and security boundaries. A full runnable program and a clearly labeled fragment have different qualification requirements. An untested rewrite does not become copy-ready from a writing score. Guide 02, its checklist template and the complete before/after example preserve those distinctions.

Fast observable first success is useful where a tutorial needs a working result. It is not a guarantee across unknown environments and does not require theory-free or executable content on every reference/explanation page. Provider verification, credentials and permissions cannot be omitted to make an example appear simpler.

## Reader calibration

Mark Baker's Every Page Is Page One principle motivates stating scope, reader, prerequisites and first-use terms even when a reader arrives from a direct link or extracted paragraph. Guide 04 preserves the four entry checks, reader questions, prerequisite examples, jargon rules, progressive disclosure and severity table. No comprehension success follows from a parse, completed checklist or persuasive analogy; actual reader response remains separate.

## Writing and review process

The ghostwriting method resolves actual mode/audience/voice/scope, drafts in that mode, then self-reviews with the complete eight-step rubric. Its voice-matching process uses authorized writing samples, explicit observed patterns and a best-effort limitation. This is a practical local procedure, not an externally validated promise of author imitation.

Docs-as-code review scopes findings to the actual changed documents and related behavior, distinguishing source/technical review from prose judgments. Existing linters can assist surface consistency and links; semantic mode/readability/reader decisions and code correctness require real review or execution. No linter, ruleset, formatter or CI tool is installed or claimed available. The scorecard and severity method provide specific locations and concrete rewrites, not a numeric source-fidelity score.

## Reference versus explanation example

Reference statement: "The fictional timeout_ms field is an integer measured in milliseconds; its actual permitted range and default must come from the real contract." Explanation statement: "A shorter delivery timeout limits request occupancy, while a longer timeout can tolerate a slow receiver; the useful choice depends on the actual retry and failure policy." The first describes a field; the second explains trade-offs. Neither establishes an installed default or permission to change a provider.
