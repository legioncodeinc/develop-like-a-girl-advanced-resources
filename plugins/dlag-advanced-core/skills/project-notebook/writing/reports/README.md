# Writing review records

A writing review records its subject/revision, six-criterion Pass/Warn/Fail scorecard, exact source locations, concrete Blocker rewrites, Suggestions, Nits and unresolved questions. Use the complete local report template. This is writing judgment, not independent implementation QA or security clearance.

Save a report only when the user requests local Markdown at an authorized project destination; otherwise return it in chat. Do not write into the installed plugin resource folder. A proposed filename is YYYY-MM-DD-[document-slug]-writing-review.md under the project's actual convention. Preserve an older review and create a new dated review when its subject changes rather than silently rewriting historical evidence. No remote PR comment, publication or external send is implied.
