# 14. Findings, metrics and notes

Read the full [output fields, severity table and examples](../references/cross-cutting/contract-output-rules.md) with the governing [local contract](../references/review-contract.md). The Specialist returns the completed report in chat; only a separately authorized caller saves or validates fresh external files.

1. Collect candidates from guides 01-13. Evidence-backed weaknesses become findings. Suspicions remain under Not confirmed with exact missing evidence; pattern hits alone never acquire High/Critical severity.
2. Set confirmed/likely/possible confidence from the actual source trace or supplied result. Record unproven runtime/identity/config steps. Shape-only secrets and unknown dependency reachability remain qualified.
3. Use the class severity table, then explain the actual actor, precondition, reachability, scale and existing controls. Do not downgrade IDOR solely because identifiers are unguessable. Confirmed unresolved Medium-or-higher findings block Quality Review.
4. Write every required field: unique `SEC-POLY-NNN`; `dimension: security`; `source: backend-security`; plain consequence; severity/confidence; relative location and positive line range; actual redacted excerpt of at most 15 code lines plus locator; impact; concrete file/change recommendation; effort; real CWE and available advisory/rule/local guide references; what ruled out false positives; optional tags.
5. Preserve every actual advisory identity and distinguish reachability. A proposed grouped upgrade must not erase independent CVE/GHSA facts. A shared generic dependency CWE alone does not merge unrelated advisories.
6. Write metrics with the actual measures from secrets/dependency/SAST/CI review plus severity counts. The local contract's verdict wins over any example. One Critical-band measure is sufficient for at-risk; a healthy verdict requires a completed applicable check. Reduced coverage remains visible independently of verdict.
7. Notes include scope/route tables, auth and ownership verdicts, checklist results, supplied tool/version/exit receipts, dropped candidates/counts/reasons, Not confirmed, Scope differences, actual scanned counts and every cap. Under `## Evidence`, list each supplied sanitized raw artifact with its purpose, or say none was supplied. No special workspace or missing global index builder is required.
8. A separately authorized capable caller may validate sanitized JSONL/JSON with `scripts/validate_findings.py`. The helper bounds input and rejects private/symlinked evidence. Structural validation does not prove the evidence true, current advisories safe, full source fidelity, deployed app behavior or an independent security clearance. Review warnings and report actual failures/corrections.
9. Return verdict, finding counts by severity, blocking unresolved findings and every coverage cap. Content authors cannot independently clear their changes. After correction, a different reviewer performs the applicable security re-evaluation before Quality Review and orchestrator repository review.

Done when required fields and semantic evidence agree, every missing check is explicit, redaction is complete, and any claimed validator result is backed by the actual output on this candidate.
