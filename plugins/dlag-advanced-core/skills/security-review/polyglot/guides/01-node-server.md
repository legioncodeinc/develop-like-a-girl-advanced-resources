# 01. SvelteKit server handlers and conditional Node services

Use the full [17-check backend catalog](../references/ecosystems/node-server.md), [Advanced request pairs](../../references/advanced-request-cases.md), [scope contract](../references/review-contract.md) and [optional-tool method](../references/cross-cutting/tool-commands.md). Read, Grep, Glob and Skill only; return the report in chat. Embedded commands are optional capable-caller reference.

1. Identify actual runtime and entry points from supplied source and deployment configuration. SvelteKit loads/actions/endpoints on Vercel own application backend work. Payload owns its separate CMS functions. Express/Fastify/Nest/Koa checks apply only to existing explicitly supplied Node code; do not install or choose one.
2. Map every route including list, export, admin, bulk operations, webhook and internal-looking paths. Record method/path/file:line, auth guard, cookie/bearer/signed-event mechanism, resource permission and expected side effects. Route names and client navigation guards do not establish auth.
3. Trace server identity. A submitted owner/user/role/id is not the actor. Verify the WorkOS user/session through the selected validated server adapter; inspect refresh, cookie propagation, logout/revocation handling and response caching. A decoded JWT or client session object is not enough. Distinguish signed bearer-only endpoints from cookie-authenticated mutations for CSRF decisions.
4. Walk N1-N17. Supplied pattern hits are candidates; read the whole handler and its helpers. Object lookups and writes need verified user plus current record/tenant permission. Every Neon query needs explicit current tenant scope; any optional RLS design must be proven against the actual role/context. A privileged client or raw-client bypass needs separate authorization.
5. Body handling: cap actual streamed bytes before parsing, validate a small concrete request DTO, reject extra privilege/owner/payment fields, and pass explicit allowed fields. A Content-Length header alone is insufficient. Any deep merge must reject prototype keys and bound depth/size; prefer avoiding generic merges.
6. Query values use bound parameters or the SDK's safe filters. Query identifiers and sort directions come from fixed maps. Do not concatenate request text into SQL/RPC or treat string-filter syntax as an authorization boundary.
7. Trace shell/code/template/file/URL sinks. Advanced stores bytes in R2 using its S3 API, not an unreviewed host upload directory. Check authenticated record-to-R2-key resolution, private delivery and expiry. For conditional Node code, separate arguments and fixed executables still need argument validation, time/output limits and stable file containment. Do not claim lexical prefixes stop symlink races.
8. For arbitrary URL fetches, prefer fixed server-selected origins/paths. Require allowed scheme/origin, credential rejection, redirect refusal, bounded response/time and no sensitive headers. If user-selected DNS targets require unavailable resolution/rebinding control, record the unresolved boundary; hostname checks alone are insufficient.
9. Inspect cookie flags and same-origin/CSRF controls on state changes, CORS allowlists, security headers, request limits, login/reset abuse controls, and production exception handling. Express `helmet`, server timeout and parser settings are conditional; SvelteKit/Vercel needs equivalent evidenced behavior, not imported Express APIs.
10. Verify secrets stay in private server environment, never Vite client variables, loader data, serialized errors, logs, artifacts or email links. R2 responses and user-specific SSR data cannot enter a shared public cache.
11. Inspect optional Stripe signature verification over original bounded bytes, durable acceptance, event/account correlation, idempotent entitlement writes and retry/recovery. Checkout success URLs are not entitlement evidence. Resend remains transactional, with recipient/actor/record permission and duplicate-send handling explicit.
12. Apply dependency, secrets, CI and error-path review. Return every route's auth/ownership verdict and each N-item's result with evidence and gaps. No search hit, successful parse or static example is an application security clearance.
