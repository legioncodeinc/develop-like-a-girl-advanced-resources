# 00. Scope and ecosystem evidence

Read the [local contract](../references/review-contract.md), [manifest map](../references/cross-cutting/manifest-to-stack.md) and [optional tools](../references/cross-cutting/tool-commands.md). This role reads only supplied scope and returns its report in chat.

1. Record owner question, candidate revision/identity, included and excluded paths, read-only boundaries, evidence source, available tools and known limits. Do not require an unavailable intake file, tier menu, global audit orchestrator, archive command or sibling cache.
2. Classify the supplied manifests by hand using the manifest map. A capable caller can separately supply bounded detector output. The helper reads only explicit scoped source/config, skips known human-document and credential paths, symlinks and embedded checkouts, and never imports project code. Its output is a classification hypothesis, not deployed-runtime proof.
3. Compare detected evidence with assigned scope. List extra ecosystems under Scope differences. SvelteKit on Vercel remains Advanced's application backend; Payload owns separate CMS functions. A package name does not prove deployed runtime. Inspect actual SvelteKit server files manually even when a classifier reports a frontend framework.
4. Build the scope table: ecosystem, path, manifest versus resolved version evidence, actual runtime/deployment evidence, framework, applicable catalog and owner. Never silently expand into someone else's paths.
5. For SvelteKit and server loads/actions use guide 01. Existing explicitly supplied Python, Go, Rust, Rails, PHP, JVM or .NET code can use guides 02-08 conditionally. Otherwise mark those catalogs N/A. Unknown code gets the cross-cutting controls and manual source-to-sink read; do not invent framework defaults.
6. Assign shared workflows, container/IaC code and deployment config to one reviewer. Containers, alternate CI and Terraform are assessed existing code only, not Advanced defaults. Record any unassigned surface.
7. Trace routes, identity, current permission, scoped data, fields, caches, files and effects, then secrets, dependencies, static-analysis evidence, CI/infra and generated-code patterns. Record every checklist row as evidenced pass, finding, N/A or NOT RUN with reason.
8. Record tool availability from supplied sanitized evidence. Do not run `command -v`, curl probes, scanners, installers or Git from this read-only role. An absent tool creates a named cap and the applicable manual method, not permission to obtain it.

Done when each assigned path has an applicable catalog and owner, route/source-to-sink evidence is locatable, excluded and unsupported surfaces are explicit, and classification limits remain visible.
