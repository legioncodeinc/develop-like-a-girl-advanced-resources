# 05. Return React findings, measures and coverage

> Advanced scope: this React catalog applies only to the separate Payload CMS. Other frameworks are conditional comparisons; no React/JSX helper inspects Svelte. Advisory versions remain historical candidates until current supplied primary evidence confirms them.

This Specialist returns its complete result in chat. It cannot write report files, execute validation commands or merge another reviewer's output. A separately authorized caller can save the result in the actual project report location using [the root report](../../references/audit-output-format.md). The optional `review-output/react/` naming below is a caller-owned organization example, not a prerequisite workspace or installed engine.

1. Collect manually confirmed candidates, supplied snapshot/version observations and unavailable scope. Use stable unique `SEC-REACT-NNN` IDs within this review. A helper candidate is not automatically a current vulnerability or production finding.
2. Preserve all fields from [the finding rules](../references/finding-rules.md): id, dimension, source label, plain title, severity/confidence, repo-relative line locations, redacted actual evidence, impact, exact proposed correction/effort, primary refs, verified_by and check tags. Bound excerpts to the necessary lines; do not reveal any credential prefix. Named APIs/helpers require actual target implementation evidence.
3. Confidence distinguishes confirmed end-to-end trace/observed fact, likely partial trace with a named gap, and possible pattern/range-only leads. A possible candidate's ranking stays at most Medium; this never reduces the impact of a later confirmed PII/payment/control defect. If no evidence beyond suspicion exists, use Not confirmed rather than inventing a finding.
4. Deduplicate one root cause/helper across many callsites; list up to twenty needed locations and state omitted count. Preserve distinct actor/effect chains and scope overlaps for the actual coordinator. Do not count a source-map flag as a key leak, or a public key as a privileged secret.
5. A caller may save one JSON object per line in a fresh `review-output/react/findings.jsonl`; parser success verifies JSON structure only. It may save matching metrics/notes separately. The Specialist itself saves nothing. No unavailable merge script or external audit contract is required.
6. Preserve measures for actual React/router/RSC versions and modes, raw HTML/untrusted paths/sanitizer evidence, Server Function authorization/validation counts when present, public-variable/credential/storage scope, backend checks/message listeners, package and generated-pattern findings. Numeric observations are context and must identify their actual source/date; stale advisory ranges cannot produce a current-safe label.
7. Notes include scope/stack table, guides applied/skipped/reasons, Not confirmed with missing evidence, dismissed counts/common reasons per check, current/unsupported handoffs, every cap and an evidence index describing each actual supplied output. Listing a planned file is not evidence it was created.
8. Findings/metrics counts must agree. Verdict is bounded to the inspected candidate and coverage. Missing material runtime/source/advisory scope blocks any blanket healthy conclusion even with zero confirmed findings. All unresolved applicable Medium-or-higher issues block Quality Review under the root gate.
9. Return exact result category: SOURCE REVIEW, supplied SYNTHETIC EXERCISE, NOT RUN, or supplied TARGET RUNTIME PASS/FAIL, plus final candidate, counts and limitations. A read-only review never claims remediation, code execution, compilation, current registry lookup or a separately dispatched Specialist without actual evidence.
