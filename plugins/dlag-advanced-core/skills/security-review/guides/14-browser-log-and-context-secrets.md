# 14. Bound browser, log and agent-context secret exposure

> Security Review uses Read, Grep, Glob and Skill on supplied local evidence and returns its result in chat. Commands, changes, scans, provider calls and test execution below are proposals for a separately authorized caller with the required tools. This Playbook does not perform them.

Use [exposure worksheet](../templates/security-design/exposure-scope.md). Sources: SvelteKit server-module boundaries, OWASP logging and secrets lifecycle, linked in the [source index](../references/official-sources.md).

1. Identify secret classes and permitted server consumers without copying values. Inventory actual production candidate bundles, prerender/SSR output, public assets, source maps, client environment exports, error responses, telemetry, request logs, CI artifacts and conversation/tool context. Public identifiers are not automatically credentials; classify authority and consequence before reporting a finding.
2. Pin build command, exact source revision, environment provenance, artifact digest and test mode. Review server-only import boundaries and public-prefix assignments, then inspect the actual built/published artifact scope available. A SvelteKit server-only module check and Vite public-variable rules depend on the actual framework mode and build. A unit test or development server cannot substitute for inspection of the real production client/SSR artifact.
3. Trace values through serialization, URLs, headers, exception/breadcrumb contexts, replay/autocapture and log exporters. Confirm masking before transmission, sink access/retention and failure logging. A default telemetry flag does not prove every custom property is scrubbed. Source-map exposure can reveal source structure or embedded literals; source maps are not automatically a credential leak.
4. Give agents sanitized minimal context. Do not echo findings' secret matches into reports, grep output, chats or source captures. Use variable names, path/line, detector class, artifact hash and redacted fragments. If inspection requires live secrets or provider controls outside authorization, stop that dependent action and retain the gap.
5. For confirmed issued-credential exposure, distinguish code removal, published-artifact removal, credential revocation/rotation and evidence of misuse. Preserve metadata and escalate the exact scope to the owner; do not read/set/rotate credentials without explicit authorization.
6. Report each inspected artifact/sink and each unavailable one, deployment/environment scope and residual access. Synthetic sentinel exercises show a procedure can catch that fixture only; no all-secrets guarantee from no matches.

Advanced uses Svelte 5/SvelteKit on Vercel, Neon PostgreSQL with Drizzle, WorkOS customer identity, Doppler secrets, R2 through the S3 API and transactional Resend. Payload 3 runs separately on Next.js with its built-in editor auth. Stripe is optional custom checkout. No newsletter or background-job provider is selected. WorkOS membership authorizes the actor; every Neon query must enforce the verified tenant/object scope. R2 access is a separate server decision.
