# Public evidence review procedure

## 1. Preconditions

Read the intake contract and write the actual available scope before reviewing. Required for a full pass: representative redacted response captures and a vendor inventory from the same engagement. If either is absent, identify the dependent work as blocked or reduced coverage; do not fabricate a scan. Existing public evidence can still support a specifically bounded header review.

Read-only observation never authorizes exploitation, authentication bypass, file uploads, credential use, checkout creation or order placement. Do not treat an interactive-mode flag in a file as human authorization. A different task with explicitly authorized operations needs its own scoped procedure.

## 2. Examine supplied captures

Record method, URL, final URL, status, redirect chain, time and capture identity. HEAD and GET responses can differ; a HEAD result does not prove GET/body behavior. A denied or unreachable request does not establish absent security headers. Use the offline analyzer only through a caller that actually has authorized shell access. Offline mode accepts supplied captures without requests. The same helper also preserves optional authorized public HEAD/GET and coarse TLS collection; using that mode requires explicit authorization for the exact target and a caller with network/shell tools. No such collection is performed by this read-only role.

## 3. Reconcile the checklist

Walk every header and cookie row, keeping presence separate from value effectiveness and contextual applicability. A string match is a candidate, not a finding. Read the CSP guide before interpreting a present policy as strong. Review multiple supplied routes where sensitive pages and public pages differ.

## 4. Cross-reference vendors

Use the supplied inventory and the vendor worksheet. Inspect the actual script policy alongside observed loader relationships. A tag manager or content tool alone is not a vulnerability. Missing inventory is a scope gap, not permission to crawl.

## 5. Disclose TLS and payment limits

Use both gap sections in the disclosure template. Retain unreviewed cipher/protocol/chain/revocation and payment script/integrity boundaries as explicit gaps. Do not score them N/A merely because evidence is absent.

## 6. Review alerts

List evidence-backed high-risk observations first and record rejected or downgraded candidates. Use the alert guide. Only an explicitly selected independent reporting rubric may assign a numeric checklist score or grade cap; the default report does neither.

## 7. Report

Return the six evidence groups in report order, with alert headline first if justified. Check the source/public boundary. If a caller is authorized to save artifacts, use its agreed paths and evidence index; otherwise return the same structured content in chat. No nonexistent scoring service or audit directory is required.
