# Report and evidence handoff

## Report order

Prepare the equivalent of six groups: supplied/redacted header observations and optional analyzer results; reconciled header/cookie checklist; vendor cross-reference; TLS/payment gaps; alert review; final summary. Chat is the default output. Only a separately authorized writer saves these groups in caller-selected paths. No fixed directory, audit plugin or scoring process is needed.

## Required row data

Every observation has route, collection time, response/method/status context, exact safe header/attribute pointer, applicability, determination, confidence and justification. Optional numeric score and weight columns appear only for an explicitly selected contract. A row without evidence/justification is incomplete, not ready for acceptance.

## Headline

Lead with evidence-supported urgent alerts and selected contractual caps, if any; distinguish the two. Then follow worksheet order so the reader can reproduce the report. Keep source-code remedies as conditional recommendations unless actually inspected.

## Limits and verification log

Carry TLS-depth, payment-integrity, authentication/session, runtime vendor and cache-isolation gaps explicitly. Keep unknown separate from not applicable. Record every rejected/reframed candidate and why. Preserve contradictory captures instead of choosing the more favorable one.

## Evidence index

When writing was separately authorized, index each saved artifact with its agreed path, producer, timestamp, evidence scope and relation to the reviewed candidate. Preserve the supplied originals separately from a redacted derivative according to the owner's data policy. Never copy real session values into a report or invent a past timestamp. In chat, use stable supplied artifact pointers and label unsaved output.

## Completion check

All available applicable rows have evidence and reasoning; alerts were reviewed even when none were justified; vendors use the actual supplied inventory; TLS/payment gaps remain visible; rejected candidates remain recorded; source/public boundaries remain clear; no collection/execution or grade claims exceed actual evidence. A limited pass remains limited after these checks.
