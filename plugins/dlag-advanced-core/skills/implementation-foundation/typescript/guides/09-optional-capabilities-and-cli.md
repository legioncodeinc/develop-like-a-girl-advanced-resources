# Optional capabilities, commands, and supplied inputs

An optional capability must state its absence and what remains safe. Catching a missing optional package and pretending a required security or authorization check passed is a failure. Keep loading behind the feature path, validate the dependency's supported runtime, and avoid top-level native or model-loading code in browser or incompatible server modules. A parser grammar dependency describes source parsing, not proof that the product contains that application language.

Advanced selects no virtual shell, shared-memory data service, vector store, model download, MCP server, background job provider, extra agent harness, or published CLI. Do not create one through a TypeScript recipe. Preserve the general boundaries: untrusted paths and command input need bounds, namespace isolation, result caps, explicit truncation, and an authorized adapter. A pathname never establishes object ownership or tenant membership. Shell-like syntax must never become arbitrary subprocess execution.

Existing Node development helpers should separate reusable pure logic from argument and input adapters. Fail with stable public messages and nonzero status on invalid input. Do not dump stacks, raw caught errors, manifest values, source lines, or credential-shaped filenames. Mutating helpers need explicit authorization, bounded destinations, idempotent writes, and tests. This packet's pure detectors do not read or mutate files. The optional Node --root caller adapter reads selected source through the declared local Core reader; it does not mutate files.

The default supplied-text mode takes one bounded JSON document on stdin with a five-second input deadline and maximum structural nesting 32. Each source text is selected and supplied by an authorized caller. In this stdin mode it cannot enumerate a repository, read a filename, import project modules, resolve tsconfig, or fetch URLs. The distinct --root mode enumerates a bounded selected source tree through the local Core reader described in scripts/README.md; it never imports or executes that project. It caps document bytes, item count, per-item bytes, total source bytes, and findings. Output uses numeric source indexes and stable rule IDs, so an adversarial filename or source literal cannot become terminal output. A source index is only meaningful with the caller's separately retained safe mapping.

A clean heuristic result means no implemented pattern matched the supplied text. It never proves validation, SQL safety, complete secret absence, compilation, schema parity, supported runtime, or reachable behavior. Rejected or incomplete input is an error, never a clean result. False positives include comments, strings, intentionally serial operations, CJS interop, and documented best-effort catches. False negatives include multiline syntax, aliases, computed imports, helper validation, and data flow.
