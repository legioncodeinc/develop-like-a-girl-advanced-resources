# Validation, DTOs, and errors

Validate request bodies, URL parameters, forms, env bindings, file or API responses, and persisted data before trusting their shape. TypeScript types disappear at runtime. `JSON.parse`, a generic client type, `as Row`, a non-null assertion, and a generated database type each provide different things; none validates arbitrary JSON by itself.

Bound bytes before parsing, collection lengths before iteration, string lengths before expensive matching, and numeric ranges before queries. Check the content type and handle malformed encoding or JSON separately from a semantically invalid field. Define the public input contract with required fields, optional fields, defaults, unknown-key behavior, dates, identifiers, and cross-field invariants. Normalize only what the contract permits. A blank value must not quietly become an authorized default principal or tenant.

Use the project's existing validator. If Zod is already installed, derive static types from the runtime schema with its matching installed API. If another validator is already selected, preserve equivalent checking. Advanced does not require a validation library installation or any protocol-specific older-major import. Evaluate server and browser bundle cost on their actual delivery paths; a deployed server function executes server code even when it has runtime and size limits. It does not send its validation library to the browser by definition. Avoid unverified benchmark or ecosystem parity claims.

Use a discriminated result for expected validation failures. Return stable public codes and safe field names, never the original body, raw exception, SQL, token, backend URL, or request header. Narrow caught `unknown` before classifying it. Even `Error.message` can include credentials or user content. Public output needs an allowlist; internal diagnostics need their own redaction and retention policy. Do not use `String(error)` as a safe public fallback.

A DTO is an explicit projection. Select only needed database columns, then construct the authorized public shape. Generating a row type prevents shape drift but does not make every column safe to serialize. Keep identity, session data, server clients, bindings, R2 objects, and secrets out of loader returns and browser state. Validate unexpected nulls and versioned stored formats. For a partially malformed result batch, either reject it or return an explicit rejected count and partial flag. Silently dropping rows while claiming completeness hides data loss.

Empty required-operation catches are failures. A best-effort operation may fail without failing the main request only when its safety, visibility, and retry behavior are deliberate. An already-exists race is tolerable only after verifying the intended final state. A comment containing the word optional is not proof. Preserve framework redirects and intentional Response throws rather than swallowing them inside a broad catch.
