# Requested HTTP review reports

Save only a requested report in the agreed local project report location. Suggested name: YYYY-MM-DD-scope-http-review.md. Preserve earlier dated evidence rather than overwriting or deleting it. Use [the complete findings template](../templates/findings-report.md).

Every report records the bounded target, actual candidate if known, evidence type, severity summary, exact method/status RFC sections or Fetch CORS references, concrete remediation and compatibility implications. It separates security, identity, platform/TLS and crawler follow-ups. Unknown or unreviewed routes are not passing coverage.

A report can be drafted from source and supplied redacted captures. Collection, shell checks, browser use, credentials, providers or settings changes require the actual capable caller's separate authorization; this local authoring method grants none. Record proposed checks as NOT RUN and avoid copying cookies, tokens, private body fields, signed URLs or raw exception text into the audit trail.
