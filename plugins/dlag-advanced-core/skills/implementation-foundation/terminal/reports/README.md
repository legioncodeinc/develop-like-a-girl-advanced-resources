# Retain only requested project-command review records

Use [the report template](../templates/findings-report.md) for source findings and operator evidence. Save a dated Markdown report only when the user requested a persisted record and its destination is authorized. Otherwise return the same complete report in chat. Do not write reports into the installed skill package, home instructions, human notes or another agent's active files.

An existing project may keep dated records such as YYYY-MM-DD-command-review.md in its accepted documentation home. Preserve older records and state the exact subject revision/dirty bytes reviewed. A new date does not prove a fresh runtime check. Report source/lint/syntax/runtime/CI/provider/native-discovery status separately and reuse unchanged passing evidence with its actual subject.

The report is an author-level project-command diagnosis, not independent Security/Quality findings authorship or a formal release verdict. No report here is auto-generated or evidence that the supplied command ran. Parent acceptance and actual independent review remain separate.
