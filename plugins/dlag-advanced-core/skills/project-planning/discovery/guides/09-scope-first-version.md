# Scope a first version from discovery

Role boundary: prepare requested local Markdown and analyze supplied evidence. The interview/test/recruiting steps below describe a plan for an authorized operator. They do not authorize contact, recording, incentives, automation, publication, credentials, provider setup, application edits or execution. Actual observed results require supplied source evidence; missing tools or approvals stay unrun.

Grounding: distillation, the desired-outcome and assumption-mapping procedures. This is a discovery handoff, not a PRD or implementation plan.

1. Choose one customer segment and one end-to-end job tied to the desired outcome. Record their source evidence and any untested assumptions. Ask only for missing decisions that change the scope.
2. Describe the smallest complete outcome: trigger, input, observable result, recovery from likely failure, and how the customer obtains value. Treat login, payment, onboarding, support, data retention, or accessibility as necessities only where the chosen job requires them; do not create a generic feature checklist.
3. Create a scope table: essential to the chosen job, manual/provisional for the learning test, deferred, and excluded. Every essential item names its supporting evidence or explicit hypothesis. Include one boundary/error case so a demo-only happy path is not mistaken for a complete job.
4. Record feasibility/operating constraints, owner time, budget assumptions, required assets/access, and highest remaining risk. Route pricing, infrastructure, security, licenses, and architecture to their selected specialist when needed; discovery does not choose a stack or guarantee an estimate.
5. Define the first-version learning/acceptance signal and the evidence that would stop expansion. Preserve existing Accepted requirements/contracts; conflicting scope becomes a separately reviewed proposal. Do not silently rewrite accepted commitments.
6. Deliver [first-version brief](../templates/first-version-discovery-brief.md) to the resolved `dlag-advanced-core:project-notebook`/`dlag-advanced-core:project-notebook` for requirements only after the owner accepts the scope and the required tested assumption evidence exists. Otherwise hand off a clearly labeled unresolved discovery brief and the next test, without an implementation-ready claim.
