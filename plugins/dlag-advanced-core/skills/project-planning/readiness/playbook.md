# Prepare a new builder for one useful slice

Turn an idea into one readiness recommendation, concrete learning prerequisites, responsibilities, unresolved decisions and a first representative slice proposal. An interview or correct worksheet does not establish competence, security or production readiness.

1. Read [goal intake](guides/interview-goal.md). Ask only missing user/job/form/milestone/experience/data/time/budget questions that change the advice; do not force a generic questionnaire.
2. Fill [the readiness worksheet](references/templates/readiness-worksheet.md). Keep reported experience separate from observed exercises and unknowns. No credentials or live-user data are needed.
3. Use [expectations](guides/set-expectations.md) and [roles](references/readiness-and-roles.md) to explain human decisions, AI drafting, actual implementation, Security before Quality, and operations. A bounded workshop analogy supports the actual software explanation.
4. Use [product-form guidance](guides/choose-product-form.md), [worksheet](references/templates/product-form-worksheet.md) and [cases](references/examples/product-form-cases.md) when the form is unclear. Recommend one provisional form only when supplied job/constraints support it. Native/mobile/host-plugin/CLI implementation is outside the Advanced web-build scope; a requirement for it remains an explicit scope/owner gap.
5. Use [beginner security guidance](guides/explain-security-responsibilities.md), the [six-boundary map](references/beginner-security-responsibilities.md), [worksheet](references/templates/security-responsibility-worksheet.md) and [cases](references/examples/beginner-security-cases.md). Identity does not imply record/file permission; unknown roles/access/understanding stay pending.
6. Propose [one representative slice](guides/choose-first-slice.md), with input, meaningful output, refusal/failure, acceptance owner and evidence needed. Defer irrelevant features/providers.
7. [Route the actual decisions](guides/route-readiness.md). Local strategy/discovery/UX/estimation methods are part of Project Planning; actual documentation uses Project Notebook and actual implementation/review uses the available Advanced methods. Do not invent unavailable roles, rates or timelines.
8. Compare the complete [worked cases](references/examples/cases.md). Return one recommendation or the precise blocking question, next learning step, role map, slice and actual handoff. Ask one respectful teach-back question; understanding remains pending until an actual reply supports a narrower observation.

This private route belongs to [Project Planning](../SKILL.md), supports Claude Code and retains the paired Specialist's expressly requested local-Markdown-only scope. Check destinations, preserve differing existing material unless its edit was requested, read back saved content and report actual paths. A requested saved draft needs no repeated permission.

The [envelope checker](scripts/check-envelope.py) checks local resource closure and three encoded advisory cases; it does not assess a learner or app. It requires Python and an authorized execution caller. The paired Specialist has no shell. Source-archive bookkeeping is not a consumer prerequisite. The [historical digest](references/research/distilled-builder-readiness.md) preserves evidence and its limits without requiring an old repository/manual.

No accounts, app scaffold, installation, source/configuration changes, paid operation, credentials, provider calls, publication, deployment, commit or push follow from readiness advice. Advanced remains Svelte 5/SvelteKit SSR, Tailwind/shadcn-svelte, Vercel functions, Neon/Drizzle data and WorkOS identity, Doppler secrets, R2, transactional-only Resend and optional custom Stripe. Payload provides the separately hosted CMS when requested; no newsletter or background-job provider is selected. Learning every technology is not a prerequisite for preparing one appropriately scoped slice.
