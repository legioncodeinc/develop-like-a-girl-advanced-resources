# Launch Assets routing

Use **Project Setup** for the bounded decisions below. Check [scope and tool limits](../scope-and-tools.md) first. A route is a proposed handoff until actual availability, authorization and a dispatch receipt are established. Implementation, provider operations and tests remain unperformed unless the capable caller supplies their evidence.

The selected stack is Svelte 5/SvelteKit, Tailwind and shadcn-svelte, Neon Postgres/Drizzle, WorkOS customer identity, Doppler secrets, Vercel application functions, Cloudflare R2 and transactional Resend. Payload CMS has its own Next.js host and built-in editor identity. Optional Stripe uses custom checkout only when requested. No newsletter or background-job provider is selected. Framework/provider-specific recipes that require another stack are unavailable. Reuse the decision criteria, inputs, negative routing and output requirements only inside that selected scope; consult the current owner's Playbook before any concrete API or configuration recipe.

**Source Specialist:** `packs/infrastructure-decision-tools/agents/Project Setup.md`.

## Domain

Prepare account, asset and platform dependency readiness without implicit setup actions.

## Trigger phrases

prepare assets; launch readiness; what accounts do I need; signing prerequisites.

## Do NOT route when

Actual account/provider setup is separate authorized work; App Primer Zero prepares repository foundations; App Store Submission owns store preparation details.

## Inputs the Specialist needs

product/platform targets, current assets/accounts, owners, environments and distribution route.

## Outputs the Specialist produces

readiness ledger, blocking dependencies, sources, lead-time/cost gaps and next owner action.

## Dispatch

Check the generated availability roster, then load the current namespaced Playbook through Skill. Confirm the actual caller and tools before work. Direct use must be labeled direct; no dispatcher receipt means no separate Specialist run.

The runtime produces an advisory artifact. No installation, credential entry, provider change, messages or release action follows implicitly. Keep the parent's scope, clock and file ownership. Code-producing changes close with Security then Quality and the orchestrator repository-health review.

the current owner's local Playbook contains the applicable domain procedure and boundaries.
