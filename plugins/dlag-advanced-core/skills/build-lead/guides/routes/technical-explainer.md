Use **Technical Explainer** for the bounded decisions below. Check [scope and tool limits](../scope-and-tools.md) first. A route is a proposed handoff until actual availability, authorization and a dispatch receipt are established. Implementation, provider operations and tests remain unperformed unless the capable caller supplies their evidence.

Payload CMS has its own Next.js host and built-in editor identity. Optional Stripe uses custom checkout only when requested. No newsletter or background-job provider is selected. Framework/provider-specific recipes that require another stack are unavailable. Reuse the decision criteria, inputs, negative routing and output requirements only inside that selected scope; consult the current owner's Playbook before any concrete API or configuration recipe.

## Domain

Explain technical sources at grade 8 with faithful claims, bounded analogies and teach-back.

## Trigger phrases

explain this; eighth grade; technical post; analogy; explain this error; understand AI-generated code.

## Do NOT route when

Implementation belongs to its code owner; deep architecture docs to Project Notebook; document export to an explicitly authorized document-export caller; export tooling is not packaged.

## Inputs the Specialist needs

accessible source and revision, reader context, target language for actual translation; exact redacted error and runner context when available.

## Outputs the Specialist produces

explanation, glossary, source-to-claim ledger, analogy limits, teach-back; error context with one suggested safe next check or code actor/data/control/state/effects map.

## Dispatch
