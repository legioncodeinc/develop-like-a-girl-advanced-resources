# Project command troubleshooting

Use **TypeScript and HTTP Foundation** for a supplied project-local command, shell script or existing task recipe. Read [scope and tool limits](../scope-and-tools.md), the owner's actual Playbook and the complete [private terminal method](../../../implementation-foundation/terminal/README.md). A proposed route is not a dispatch receipt. The Foundation role has no Bash and grants no execution, installation or shell-setting authority.

## Domain

Diagnose actual invocation/cwd/interpreter/arguments, missing existing project commands, quoting/status/cleanup/output boundaries and the semantics of existing package, make or just recipes. Preserve the selected SvelteKit/Vercel/Neon/R2 stack, installed tooling and project file ownership. Use source inspection and expressly requested safe local authoring; report operator checks as NOT_RUN unless actual evidence exists.

## Trigger phrases

- Review this project shell script.
- Explain why this existing package command fails.
- Check the arguments and error handling in this script.
- Diagnose this Makefile target or existing just recipe.
- Explain the search/output behavior of the command this project already uses.

## Do not route here

- Global dotfiles, shell defaults, prompts, tmux/Zellij, tool adoption/installation or workstation bootstrap: separate operator scope, unavailable in this method.
- CI/container implementation or publishing/deployment: GitHub Workflow can inspect existing CI evidence; a capable designated execution owner is required for changes/effects.
- Python build/test pipelines: separately qualified Python owner; no selected Python implementation is inferred.
- Production infrastructure hardening: actual Security Review plus the authorized operator.
- OS/kernel/service administration or a new task-runner migration: outside this bounded troubleshooting method.

## Inputs

- The exact supplied project script/recipe and safe invocation.
- Expected behavior and actual redacted failure/output/status, if observed.
- Actual cwd, OS, interpreter/invoker/version and required portability, or the precise unknowns.
- Authorized files and proposed change scope; existing tools/package manager/runner.

No home dotfile/history/credential/environment dump is needed. Ask only unresolved material questions. Do not launch a version probe, command or preview from the no-shell role.

## Outputs

- Source-backed diagnosis and exact line/behavior references.
- A precise interpreter-appropriate local correction/proposal within actual file-authoring authorization, preserving ordinary argument boundaries, status behavior, effects and unrelated work.
- A complete scoped findings report with severity/rationale, actual evidence, unrun operator checks and residual limits.
- Actual selected CI/Python/security/execution handoff or the exact unavailable capability; no invented dispatch or global configuration file.

## Review order and limits

Source review, saved proposal, syntax/lint, task runtime, CI, native discovery and provider/release evidence remain separate. Component acceptance requires Security Review, fixes/rechecks, independent Quality and coordinator-direct GitHub Workflow repository-health. A missing required capability leaves that gate NOT_RUN/unfinished. No plan, example, route or report authorizes secret reads, installation, shell/configuration changes, remote execution, spend, sends, commit, push or deployment.
