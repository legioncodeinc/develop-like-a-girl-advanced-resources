# Why a routing guide needs judgment

Build Lead keeps coordination narrow so each available method can be applied by a qualified caller with a clear responsibility. The coordinator's confidence cannot replace subject expertise or actual evidence.

The first rule is to select the right owner for the specific task. Security analysis belongs to Security Review, while implementation fixes belong to an authorized implementer. Documentation authorship belongs to Project Notebook; verifying implementation against an approved plan belongs to Quality Review. A title or shared keyword does not settle those boundaries.

The second rule is to pair the selected owner with its actual available Playbook before work. A persona without its method is an incomplete handoff. A method named in a broad reference is still unavailable until the host's selected roster and registered skill establish it. A direct review is useful when allowed, but it must be labeled honestly.

A manifest says what exists. The routing guides add context: domain, positive triggers, negative triggers, inputs, outputs and useful sequences. Read these before dispatch. Misrouting creates unwanted work, an unusable artifact and avoidable follow-up.

New capabilities require deliberate product authorization, research, scoped method writing, local references, guides, a public entry, a qualified owner and validation of actual availability. This routing task does not create or register them. Keep that lifecycle outside the current fixed roster. A future method needs traceable evidence and repeatable checks before it can support a release claim.
