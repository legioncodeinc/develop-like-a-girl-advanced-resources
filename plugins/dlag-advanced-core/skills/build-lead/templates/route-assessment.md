# Route assessment

- Requested outcome: [the user's concrete result]
- Candidate available owner: [registered namespaced capability or unavailable]
- Domain fit: [why this method owns this result]
- Positive triggers: [matching task evidence]
- Negative routing: [neighboring methods and explicit boundaries]
- Required inputs: [supplied locations; unknowns that block dependent work]
- Expected artifacts: [form, scope and evidence, not a claimed result]
- Required sequence: [dependencies, accepted boundary pins, independent reviews]
- Tools and authorization: [actual caller; direct or dispatched evidence]
- Stop conditions: [missing method, unsupported target, deadline or failed prerequisite]
- Owner decision: [one concrete question only if the task depends on it]

Prefer the narrower qualified owner when two domains overlap. Preserve the broader owner as a supporting review only when needed. Do not change the public roster or register a new command through this worksheet.
